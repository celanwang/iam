# 长连接网关设计

IAM 的长连接入口使用 TCP + TLS 和现有 Protobuf 协议。网关管理 socket、接入和流控，消息服务管理设备会话、消息提交和恢复。在线推送负责及时通知，发送结果以 TiDB 提交为准，设备通过 `SYNC` 补齐漏收。

| 阶段 | 部署方式 | 交付范围 |
|---|---|---|
| 已有基础 | 进程内协议调用和真实 TiDB | 发送结果查询、同设备接管、生成推送帧、客户端持久发送和同步恢复 |
| 首期接入 | 独立 Rust 网关模块与消息服务同进程，单实例 | TCP + TLS、正式鉴权、接管、实际推送、背压、重连与网络故障验收 |
| 同地域生产部署 | 多可用区网关实例独立部署，共享会话路由和消息服务 | 连接发现、跨实例接管、定向推送、滚动发布与故障切换 |
| 跨地域扩展 | 地域入口和就近接入，业务按写入归属路由 | 接入故障转移、跨地域定向推送，按地域实测验收 |

## 单实例运行

`iam-gateway` 可直接启动 TCP + TLS 监听。启动时从 PEM 文件加载证书链和私钥，从设备凭证文件加载租户、用户、设备 UUIDv7、授权到期时间（Unix 毫秒）和原始访问令牌的 SHA-256 十六进制摘要。每行一个设备，字段用空格分隔。调用方为每台设备签发独立的高熵随机令牌，客户端在 `AUTH` 中传原始令牌。会话和恢复票据沿用原授权到期时间。

```sh
IAM_GATEWAY_BIND=127.0.0.1:8443 \
IAM_TLS_CERT=/path/to/chain.pem IAM_TLS_KEY=/path/to/key.pem \
IAM_DEVICE_CREDENTIALS=/path/to/devices.txt \
IAM_TIDB_URL='mysql://root@127.0.0.1:4000/iam_local' \
IAM_STORE_ID=018bcfe5680070008000000000000002 IAM_TIDB_MODE=resume \
cargo run -p iam-gateway
```

`resume` 使用已初始化的同一 TiDB 库和存储 ID。新库用 `fresh` 初始化，部署方通过 `TidbService::create_direct` 预置会话，或接入已配置会话的本机库。客户端使用 `iam_client::TlsTransport` 并提供信任根和预期证书名称。外部身份提供方属于后续接入。

在 Unix 上，更新证书链、私钥和设备凭证文件后，向实际运行的 `iam-gateway` 进程发送 `SIGHUP`。网关校验整批配置，成功后新握手使用新证书。凭证删除、轮换或修改到期时间会关闭对应设备的连接并作废旧恢复票据。凭证相同的设备继续使用当前连接。空凭证文件撤销所有设备。文件读取、解析或证书与私钥配对失败时，网关记下错误并继续使用上一次配置。

嵌入应用可调用 `Gateway::reload` 更新配置，或调用 `Gateway::revoke_device` 立即关闭指定设备的连接并禁用当前进程内的凭证。跨重启撤销由部署方从凭证文件删除旧凭证。

## 性能目标与现有基线

[整体设计](./design.md)以同地域服务端核心链路 P99 小于 10 ms 为目标。网关用单调时钟记录两个端点，从 TLS 解密后的完整 `SEND` 帧进入网关读缓冲，到回执的 TLS 数据写入 socket。帧校验、入站排队、服务处理与 TiDB 提交、出站排队及写入均计入。另记 TLS 握手和整帧读取（含解密）、提交到在线推送、客户端重连补齐的时间。总 P99 由单请求的完整耗时计算。

现有 [TiDB 压测](./tidb-perf.md#时钟采样合批对照)没有经过 TCP + TLS。开启合批后，两轮纯发送 P99 为 8.45 / 7.37 ms，空 `SYNC` 并发时为 15.74 / 12.19 ms，集中重连时为 16.10 / 9.50 ms。这说明混合负载下，保护发送免受后台流量争用比减少单次转发的微小开销更紧迫。网关的延迟预算需用同一负载下的接入前后对照确定。

连接容量按峰值在线**设备**数估算。以每台设备每 30 秒一次心跳为例，100 万在线设备平均产生约 3.3 万次心跳/秒，集中上线时峰值还会更高。单实例分别测空闲连接数、TLS 握手速率、活跃吞吐、在线设备扇出和恢复吞吐。

## 职责边界

| 职责 | 网关 | 消息服务 |
|---|---|---|
| 连接 | TLS、收发帧、超时、socket 和写队列 | 分配 `connection_id`，维护已认证会话、同设备接管与能力协商 |
| 鉴权 | 接入限额、连接状态、转交凭证 | 验证身份和设备绑定，签发及校验恢复票据，处理撤销与会话失效 |
| 消息 | 按连接转发请求和应答，按 `connection_id` 投递推送 | 会话权限、持久化提交、去重、发送结果、推送目标及同步 |
| 过载 | 控制接入和转发速率，保护进程内存和连接 | 限制业务及 TiDB 开销，返回提交结果或协议规定的暂时状态 |

网关把 socket、连接阶段、空闲计时和写队列保存在内存中。握手后先用本地句柄识别 socket，认证成功后才登记 `connection_id → socket 写队列`。消息服务维护 `(tenant_id, user_id, device_id) → 活跃 connection_id`，并决定向哪些已认证连接生成推送。两张映射都随连接释放。发送记录和客户端同步游标独立于连接生命周期。

接入接口接收网关绑定的连接句柄和完整帧，返回当前请求应答及带目标连接 ID 的投递事件。首期适配 `TidbService::handle_frame` 与 `disconnect`。适配层将 `EngineOutput.pushes` 中的连接级关闭事件与普通推送分别入队。网关从本地 socket 绑定取得连接身份，关闭与投递均按该连接实例匹配。

## TCP + TLS 接入

- 首期建议专用 TCP 端口、TLS 1.3，客户端校验证书链和服务端主机名。关闭 0-RTT，避免握手前数据重放。证书轮换对新握手生效。参见 [RFC 8446 §8](https://www.rfc-editor.org/rfc/rfc8446.html#section-8)。
- 分别设置 TLS 握手、认证、整帧读取和 socket 写入的期限。整帧读取用总期限，避免逐字节发送延长等待。TLS 握手前限制并发握手数和每来源接入速率。
- 复用现有帧解码器。读满 12 字节固定头后检查版本、标志和长度，再读剩余数据。遵守整帧 1 MiB、`Head` 256 字节及协商上限，处理半包和连续帧。长度非法、残帧断开或读取超时直接关闭；版本、线格式和请求号错误沿用协议的错误及关闭规则。

握手压测区分完整 TLS 握手与 TLS 会话恢复，分别记录 CPU、成功率和握手时延。TLS 会话恢复仍从应用层未认证状态开始，必须通过 `AUTH` 或 `RECONNECT` 校验身份。

## 鉴权与连接管理

连接依次进入握手、未认证、认证中、已认证、关闭。未认证连接只进入 `AUTH` 或 `RECONNECT` 处理，业务请求按协议返回 `UNAUTHENTICATED`。同一 socket 的入站请求按顺序派发，首期只同时处理一个请求，有界等待队列与它一起计入协商的并发上限。不同 socket 可以并行，沿用现有 TiDB 时钟采样合批。

正式鉴权由消息服务调用统一的凭证验证接口。验证结果给出可信的租户、用户、设备绑定、授权到期时间和撤销标识。现有种子凭证用于测试。网关使用服务确认的身份和能力执行连接级限流，日志排除凭证和消息正文。`RECONNECT` 校验恢复票据的身份绑定、到期时间和撤销状态。票据无效时重新 `AUTH`，暂时过载时按退避重试。恢复票据的有效期受原授权约束。会话绑定前再次确认授权仍有效，防止验证期间发生撤销后又激活旧授权。授权到期或获知撤销时，服务停止该会话准入并通知网关关闭。

凭证验证单独限制在途数和等待时间。身份提供方变慢时优先保护既有有效会话的业务容量，新认证按过载规则退避。压测分别计量凭证验证、会话登记和 TiDB 时钟采样，避免把身份提供方的瓶颈计成握手成本。

同一实例按 `(tenant_id, user_id, device_id)` 接管连接。接入适配层按消息服务确认的会话变更顺序发布绑定、认证应答与接管事件。发布只做内存状态更新和有界入队，socket 写入由写任务完成。若认证结果迟到且该连接已被接管或断开，适配层不激活该 socket，并按本次分配的连接 ID 清理会话。旧 socket 停止接收业务请求，清除待发普通推送，再尽力写 `SESSION_REPLACED` 后关闭。已经交给消息服务的 `SEND` 可以继续结算。

默认按协议使用 30 秒心跳和 90 秒空闲超时。网关用本地单调时钟记录最近有效入站帧，消息服务生成 `HEARTBEAT_ACK`。EOF、超时、接管、写入失败和停机使用统一的关闭流程，停止接收新请求并通知消息服务清理会话。

### 心跳与存储隔离

现有 `TidbService::handle_frame` 为每个 `HEARTBEAT` 单独调用 `database.now()`，会开事务并锁 `store_control`。首期以该路径作为压测基线。若锁争用成为瓶颈，验证由消息服务在内存中处理心跳，仍校验会话、授权有效期、撤销状态和 `req_id`。`HEARTBEAT_ACK.server_time_ms` 用于协议回包。授权到期、恢复票据和发送窗口各自使用对应的授权或存储时钟。

当前心跳也会记录业务空闲期间观察到的最大数据库时间，推进关闭水位。切换前需验收数据库时钟跨过发送窗口或票据期限后回拨，检查旧键关窗、未决发送查询和票据到期。若改用存储层定期采样，也要覆盖时钟在两次采样之间跨过期限又回拨的情况。只有明确采样间隔的影响并验证关闭水位和凭证到期规则后，才切换线上心跳路径。

## 基本流程与并发模型

1. **接入**。完成 TLS 后处理 `AUTH` 或 `RECONNECT`。消息服务确认身份并分配连接 ID，网关登记连接，把认证应答作为该会话第一帧写出。
2. **上行**。网关读完一帧后按连接顺序转交消息服务，沿用请求的 `req_id`。对 `SEND`，消息服务确认 TiDB 提交后才返回 `committed`，网关原样转发。发送端未收到结果时，用原 `client_msg_id` 查询或重试。
3. **下行**。消息服务提交后生成 `PUSH`，指定目标连接 ID。网关找到对应写队列并投递。认证应答还未写出时，普通推送按队列预算暂存或丢弃。接收端通过 `SYNC` 补齐漏收。
4. **断开**。网关撤销本 socket 的投递映射、释放队列，再按连接 ID 通知消息服务。重连分配新连接 ID，客户端沿用同设备的待发消息和同步游标。

首期每条连接设一个读入与派发任务、一个写入任务，收发可以同时进行。读侧按顺序处理请求，同一连接最多一个业务请求进入消息服务，等待空间用完时暂停读取。读写、关闭和等待派发各有期限。请求校验与拒绝共用消息服务入口的一份请求号水位。写侧负责完整帧、排队和写超时。

网关在转交请求前为其取得服务在途配额。转交前超时可拒绝本次尝试。转交后的 `SEND` 由消息服务持有在途配额直到结算，即使 socket 已关闭。等待结果超时可关闭连接，客户端用原键恢复。停机先停止新请求转交，再等服务结算和回执写出。达到排空期限后关闭剩余连接，发送结果沿用存储的故障恢复规则。

同一连接上的大页响应可能占住写入者，慢请求也可能挡住后续心跳。首期用较小的分页字节上限、单请求期限和有界等待控制这两段阻塞，并测量同一连接上 `SYNC` 与心跳或发送并发时的尾延迟。验收发现读侧等待是主要成本时，再考虑拆分读帧与派发，仍按原顺序完成连接校验与业务准入。

## 推送与背压

每个 socket 只设一个写入者，按完整帧写入。控制帧与发送结果优先，分页响应次之，推送最低。认证应答先于该会话的第一条推送。调度只选择尚未开始写入的帧，按字节限制每轮连续写入并为分页响应留出服务机会。接管和撤销发生时，写入者先停止普通推送。有半帧在途且无法在期限内完成时，直接关闭 socket。仍能完整写出终止帧时，发出后关闭 socket。

投递队列同时限制每连接的帧数、字节数和等待时间，并设实例总字节预算。为控制帧和请求应答预留空间。慢连接的普通 `PUSH` 可以丢弃，客户端按原游标通过 `SYNC` 补齐。控制帧或请求应答无法在预算内写出时关闭连接。已提交但回执丢失的发送由客户端用原键查 `SEND_STATUS` 或重试。socket 写入成功及可选 `PUSH_ACK` 都不推进同步游标，也不产生“已送达”回执。

### 资源预算与过载处理

连接级和实例级字节预算覆盖读帧缓冲、队列、正在写入的帧和应用持有的 TLS 缓冲。校验长度后先取得预算再分配大块缓冲，空闲连接按需增长，超时、取消和关闭时释放配额。分别观测进程内存和内核 socket 内存、文件描述符、握手数及调度延迟。由高低水位控制暂停与恢复读取，连续过载时按压力来源降低新工作量。

入口限额分三层。

- **未认证接入**按来源和实例限制连接数、握手数与认证速率。
- **已认证连接**按连接、设备或租户限制请求数、字节数和在途请求数。读入预算耗尽时暂停 socket 读取。若已经读到可关联请求，在消息服务的统一入口完成协议校验并记录请求号，再按原因返回 `RATE_LIMITED`、`RESOURCE_LIMIT` 或 `OVERLOADED`。入口错误只表示本次尝试未进入业务处理。客户端重试使用新 `req_id`，发送仍沿用原消息键。
- **消息服务预算**为 `SEND`、`SEND_STATUS`、连接控制和增量 `SYNC` 留容量，给 `SNAPSHOT` 和 `HISTORY` 设单独的在途上限。网关根据服务公开的负载与请求类别做准入，消息服务按实际页数、读取量和 TiDB 并发兜底。当前按可识别的请求类型计费。重连后的增量请求要和定期 `SYNC` 分开限额，需先定义服务可识别的恢复状态。

写队列压力升高时先减少普通推送，慢连接超时后回收。服务处理排队升高时限制新认证和重型恢复，保留状态查询和定期补齐。实例接近硬上限时停止接入新连接。监控按阶段和命令记录在途、队列等待、拒绝、丢推和关闭原因，避免用每个连接 ID 作为指标标签。

### 热点会话扇出

当前 TiDB 提交后，消息服务持有共享引擎锁，逐成员遍历活跃连接并生成 `EngineOutput.pushes`，完成后才返回发送回执。网关丢推已经晚于扫描和编码。首期分别记录提交完成到回执可入队的耗时、引擎锁等待、候选连接数、实际目标数和编码字节。

若压测确认这一段拖慢发送，先按 `(tenant_id, user_id)` 索引活跃连接，缩短锁内选目标的时间，再让回执先入预留队列，普通推送按批走有界分发。推送预算前移到编码前，超预算仍由 `SYNC` 补齐。字段一致时可复用不可变的消息数据，连接独有的 `push_id` 和访问版本分别编码。优化前后一起测在线推送延迟、丢推率和由此增加的同步量。

### 集中重连与发布

TLS 握手、认证和重连后的补齐分别限额。未认证连接的 `AUTH`、`RECONNECT` 和已认证连接的 `SYNC` 在对应配额耗尽时可等待最多 75 ms。认证和同步各有独立的等待上限，默认分别为 32 和 16。等待占用现有读缓冲预算，连接关闭、授权到期或网关停机时退出等待。队列已满或等待超时按协议返回 `OVERLOADED`。

客户端成功认证后立即同步，成功同步后按固定周期检查。失败时遵守 `retry_after_ms` 并按本地策略退避，握手前被拒或直接断开时走本地退避。已经进入提交的 `SEND` 仍用原消息键查询或重试。

计划停机时先停止新接入，再按批次排空现有连接。在具备多个接入实例后，用剩余实例在故障下的握手、认证和补齐容量决定发布批次。客户端在新连接上继续使用已持久化的发送队列和游标。

## 连接发现与故障切换

首期客户端使用预置域名和端口。同地域部署时，域名指向跨可用区的四层入口，入口把新连接交给健康且可接入的实例，并尽量保留排空中的现有连接。探活分别看进程存活、接入就绪和实际剩余容量。单实例超载或进入排空时减少新连接，已有连接按当前预算继续服务。发布和单可用区故障都以剩余容量为准，分别检查握手、鉴权和补齐限额。

需要按地域、运营商或实际建连成功率选址时，再增加可选的端点发现服务。它从服务发现取得可用入口，按健康、容量和地域约束返回少量带有效期的候选。客户端优先尝试最近成功的有效候选，失败后按退避切换；发现不可用或缓存到期时回退到预置域名。所有候选都校验预期的 TLS 服务名。发现服务可独立更新，既有连接无需重新查询。扩容、缩容或端点排序变化只影响新连接。

连接健康以协议心跳和有效入站帧判断。网络切换、半开连接或网关故障都通过重新建连恢复，成功后用同一设备的本地队列和游标续跑。对普通断开保留带抖动的重连，收到 `SESSION_REPLACED` 的旧客户端停止自动争抢。

## 跨实例会话与定向投递

### 会话归属

同一设备在整个接入范围内只有一个会话归属，以 `(tenant_id, user_id, device_id)` 为键。消息服务的会话控制面是唯一登记方，按键分片并使用支持原子条件更新的共享状态。记录包括 `connection_id`、递增的会话代次、网关实例 ID、地域及租约。网关实例 ID 随进程重启变化。按 `(tenant_id, user_id)` 可批量查到在线设备的归属。网关只维护本机 `connection_id → socket`，不持有会话成员关系。

1. `AUTH` 或 `RECONNECT` 校验成功后，会话分片用条件更新登记一个待激活代次，并停止旧代次的业务准入。同一设备同时只处理一次接管，其他认证尝试按协议退避。旧网关停止读入业务和写出普通推送后，回报停用的连接 ID 与代次，并尽力发送 `SESSION_REPLACED`。
2. 新连接在旧连接确认停用，或旧代次可能持有的最后一份租约到期后，以条件更新激活并返回认证成功。会话分片串行处理接管和续租。接管记录旧代次已获准的最晚期限，后续续租带上此前未确认的撤销。网关先停用这些代次，再启用新的续租期限。续租按分片所有权代次与递增序号应用，防止迟到的响应覆盖已生效的撤销。候选连接断开或等待超时后按代次清理，保留旧代次的停用状态和最晚租约期限，供下一次接管判断。
3. 每次转发、关闭和推送携带连接 ID 与代次。消息服务在业务准入时校验归属，网关只向对应的本地有效代次写出，迟到的断开只清理原代次。已经准入的 `SEND` 可以继续结算，已写入 socket 的字节也可能晚到，客户端沿用原键和会话顺序处理。

网关用本地单调时钟和保守的漂移余量计算租约截止点，到期即停止转发和写出。每个网关按涉及的会话分片批量续租，同一分片上的连接共用租约。分片故障恢复时，需从共享状态恢复已授予的最晚租约期限，或等待旧分片可能发出的租约全部过期。归属缓存用于找推送目标，认证、接管和业务准入由持有有效分片所有权的消息服务校验代次。分片不可用时暂停其新认证、接管和业务准入，已准入请求仍可完成。正常请求复用分片内的会话状态，心跳和每条消息无需写共享路由存储。拆分部署后单独测路由与内部 RPC 的延迟。

### 推送路由

消息服务提交后确定有权限的接收设备，批量查在线归属，按目标网关分组。首期用进程内接口投递。拆分后使用带双向认证的内部 RPC，复用连接，转发请求时绑定来源网关和已认证会话，内部接口区分请求应答、撤销或关闭、普通推送。控制和回执使用预留容量，普通推送有独立的字节上限和期限。网关返回的是本地入队或拒绝结果，设备同步进度仍由客户端落盘维护。

单聊和小群统一走定向投递，查询范围只包含有权限的接收者。网关成员变化由发现与归属更新处理，用户的 socket 无需跟随哈希环迁移。大群压测若显示逐设备查路由占主导，可按确有接收设备的网关聚合投递，仍由消息服务提供已授权目标和访问版本。全网广播、独立路由服务和跨机房 MQ 的引入条件分别用无效流量、路由开销和跨地域积压实测判断。

设备路由暂不可查、目标网关不可达或推送队列已满时，普通推送在预算内结束，发送回执仍以持久提交为准。上行 RPC 超时且无法确认是否准入时，网关关闭连接，客户端用原 `client_msg_id` 查询或重试未决发送。收件端保持在线时按期同步，重连后立即开始补齐。归属和投递服务恢复后继续发送后续实时推送。

## 多机房与跨地域

先实现同地域多可用区，按剩余容量和实际恢复时间验收。跨地域时客户端优先连网络质量较好的允许入口，消息服务按数据归属转发业务请求。同一会话仍有唯一写入归属，设备归属也只由该设备的会话权威分片决定；跨地域路由缓存只用于定位。跨地域推送按目标地域和网关聚合，使用有截止时间的异步投递，独立限流并记录延迟、丢推率和后续补齐压力。

网关地域故障时，客户端通过其他入口重新鉴权，继续访问仍可用的会话分片和消息写入归属。会话分片迁移须先隔离旧分片，等旧租约失效后接管。若故障涉及存储或写入归属，按 [迁移与故障隔离](./design.md#分片迁移与故障隔离) 处理旧写入方隔离、复制进度、去重和游标衔接。跨地域上线前需要明确可接受的数据损失与恢复时间，并演练切换与回切。跨地域链路的 P99 单独统计。

## 首期验收

| 场景 | 验收结果 |
|---|---|
| TLS 握手失败、证书轮换、半包和超限帧 | 客户端校验服务端身份，新连接使用新证书，网关按协议处理残帧且缓冲有上限 |
| 证书和凭证热更新 | 新握手使用更新后的证书，变更设备的旧连接和恢复票据失效，其他设备继续收发。无效配置保留原配置 |
| 凭证过期或撤销、设备绑定不符 | 无效身份无法发业务请求，撤销后的旧会话关闭 |
| 身份提供方变慢或超时 | 新认证有界等待，现有有效会话的发送与状态查询仍有容量 |
| 同设备接管、认证期间断开 | 旧连接停止转发，接管通知优先投递，认证与断开竞态不留下幽灵会话 |
| 提交后断连或网关重启 | 原键能查回执，接收端重连后用持久游标补齐 |
| 转交前排队超时、转交后断线 | 前者可返回入口拒绝，后者在途配额保留到结算，重连可用原键查结果 |
| 慢连接、首条或末条推送丢失 | 单连接写队列有界，其他连接可继续发送，漏推可通过 `SYNC` 恢复 |
| 大页响应与慢写 | 半帧超时后关闭连接，控制帧和发送回执只在完整帧边界调度，连接和实例的字节预算都能回收 |
| 心跳和空 `SYNC` 同时到期 | 记录心跳吞吐、时钟事务和控制行等待，验证心跳隔离后回拨、关窗和撤销语义 |
| 租户突发与热点扇出 | 测正常租户的发送和补齐长尾，记录丢推后的额外同步开销 |
| 集中重连、发布或实例退出 | 测持续发送下的握手及认证成功率、补齐耗时、剩余容量，以及已提交未收到回执的恢复 |

容量测试先用真实 TCP + TLS 和可控延迟的服务替身找出每实例的连接、CPU、内存和队列上限，再用真实 TiDB 复跑纯发送、并发认证、空 `SYNC`、集中重连，叠加表中的故障。固定外部到达速率逐档加压，报告计划到达、实际发出、网关准入、完成、拒绝和超时量，同时记录 P50/P95/P99。补齐从客户端开始重连计到消息及游标落盘。现有 [消息可靠性验收](./message.md#怎么验收)作为恢复语义基线。

```sh
IAM_TIDB_TEST_URL='mysql://root@127.0.0.1:4000/iam_test' \
IAM_TIDB_ALLOW_TEST_WRITES=1 \
cargo test -p iam-gateway --test tls -- --ignored --skip capacity::
```

首期优先验证心跳隔离、收发字节预算、发送和恢复的容量保护，以及发布排空。在相同硬件、负载与故障下找到首次无法满足发送 P99 或恢复目标的负载，再根据可接受的拒绝率和故障余量确定实例容量。若剖析显示复制、编码、调度或系统调用成为主耗时，再比较连接表分片、批量写与 `TCP_NODELAY`。

真实 TCP + TLS 和 TiDB 下的固定速率发送、集中重连和慢读对照见 [网关容量压测](./gateway-perf.md)。

## 多实例与跨地域验收

| 场景 | 验收结果 |
|---|---|
| 发现服务不可用、候选全部失效 | 既有连接继续，客户端用有效候选或预置域名恢复新连接 |
| 同一设备跨网关并发认证，候选断开，接管通知与续租乱序 | 同一时刻最多一个代次可以准入新业务。候选取消后下一次认证仍须等待旧代次停用或到期，迟到的续租、断开、撤销和推送只作用于原代次 |
| 路由不可查、跨实例 RPC 超时或重复 | 普通推送的队列和等待有界，回执由提交状态决定，收件端可同步补齐，错误路由不会投到其他设备 |
| 单可用区退出、滚动发布与集中重连 | 测持续发送下的接入成功率、发送 P99、补齐耗时和剩余容量，避免恢复流量挤占现有连接 |
| 跨地域网络分区、入口故障和回切 | 可用入口接管新连接，消息写入继续遵守唯一归属；回切验证去重、游标衔接和实测恢复时间 |

接入成功率按有效设备的接入尝试统计，TCP、TLS 和鉴权分阶段记录。过载拒绝、连接超时和重试耗时一并报告，凭证无效另计。在线推送从提交计到客户端应用。末条漏推从提交计到消息及游标落盘，故障重连另记从断线到补齐的时间。报告故障范围、观察窗口和未恢复比例。系统可用性与已确认消息持久性分别验收。 [整体设计](./design.md)

## 实施前确认

- 身份提供方、设备绑定依据，以及撤销通知的传播时限。
- 峰值在线设备数、活跃比例和单设备补齐目标。网关的连接、握手、队列字节和恢复流量预算以真实网络压测结果定值。
- 同地域部署时选择会话归属的存储实现，实测条件更新、租约失效和故障恢复。
- 跨地域部署前确认允许接入的地域、数据归属以及存储切换的恢复目标。
